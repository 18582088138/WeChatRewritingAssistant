# 如何通过 prompt 调整栏目语言风格

目标是稳定生成专业、自然、克制的中文科技解读，同时保留读者理解技术所必需的指标、条件和边界。风格需要对固定样本反复比较，不以一次生成或审稿分数定论。

## 配置职责

| 文件 | 职责 | 建议修改 |
| --- | --- | --- |
| prompts/rewriting.md | 新论述结构、输出契约、来源和图文要求 | 不随风格实验频繁改动 |
| prompts/language-style.md | 栏目口吻、句式、细节密度、标题与结尾 | 优先调此文件 |
| prompts/reviewing.md | 技术事实、来源、语言及排版评价 | 为风格新增可检查的标准 |
| prompts/fusion.md | 多来源选区融合、合法出处、局部插入 | 保留选区和来源约束 |
| prompts/compression.md | 实质删减至篇幅预算 | 保留数据条件和来源，不只同义改写 |
| generation.json | word_count/style/temperature/max_tokens/模型和超时 | 控制实验变量 |

统一风格文件会拼接进写作、压缩和参考融合提示词。单篇 GUI 的 style 是额外写作要求，实验时保持与统一风格一致，避免一边要求“克制”一边要求“震撼”。局部选区任务还会有独立修稿要求。

## 可执行的风格约束

不要只写“去 AI 味”“更专业”。把感受改成输出能观察的规则：

```text
开头两三句说明谁发布了什么，哪些读者会受影响；不写行业泛泛背景。
每段围绕一个事实或判断，通常二至四句。数字和适用条件放在相邻句。
首次出现术语时用一句话解释，不把专业名词全部删掉。
判断前先给证据；厂商数字写“报告/声称”，没有独立复现时明确说明。
不要每节重复“这意味着”，不要假装测试、采访或亲历。
结尾指出一个仍需验证的具体问题，避免口号。
```

正负例可以显著降低歧义，但不得让模型把例子中的虚构数字带入新稿。示例需注明“只示范表达，不是事实来源”。

| 希望改善的表达 | 有问题的示例 | 更合适的表达示例 |
| --- | --- | --- |
| 结论强度 | “22 ms 延迟让语音交互彻底实时化。” | “报告给出的 22 ms 是该处理模块的固定算法延迟，不能直接代表整条交互链路。” |
| 测试条件 | “模型速度提升 2.29 倍。” | “作者在所述硬件与音频长度条件下报告 2.29 倍推理加速；更换实现后仍需验证。” |
| 新闻开头 | “AI 的浪潮正在以前所未有的速度改变世界。” | “团队发布了两款语音增强模型，分别处理说话人分离与回声消除。” |
| 标题 | “炸裂！国产模型杀疯了！” | “模型开源后，哪些能力可直接使用，哪些仍受接口限制” |
| 分析与事实 | “这证明它已全面超过竞品。” | “这项结果对应特定评测，尚不足以概括全部使用场景。” |

## 一轮可复现的调整

1. 选定至少三种样本：技术论文、模型发布、行业事件。可复用本轮两篇公众号文章与一篇智东西文章。固定资料包、目标字数、模型、temperature 和平台。
2. 保存当前 config 副本或 Git commit，记下 config_version、文章 revision 和实验目的。生成记录的 config-history 保存本地配置快照，generated/attempts 保留原始及压缩输出。
3. 每轮只调整一类规则，例如“开头删泛背景”“数字与条件相邻”“减少机械总结”。不要同时改模型、字数、温度和十条风格规则。
4. 使用相同资料关闭重新联网检索后再生成，减少来源变化影响。再次生成通常把现有稿作为上下文，若要比较完全新稿，可新建任务并使用相同材料包，记录这一差异。
5. 先读稿再读审稿。逐项记录开头是否具体、事实条件是否丢失、句式是否重复、原文结构是否复刻、图注是否自然、结尾是否有具体问题。最好保留让你不满意的原句与期待改法。
6. 同一配置至少看两次输出，再对另外两种样本复验。模型有随机性，一篇更顺并不代表风格稳定。
7. 保留有效规则，撤回造成技术信息丢失或所有文章趋于同模板的规则。把采用原因写入自己的风格变更记录。

## 常用调参方向

表达太夸张：限制结论强度，要求“事实 → 条件 → 分析”，加入具体夸张词反例，要求厂商声明明确归属。不需要把所有观点都删掉。

太像论文摘要：指定读者和应用问题，首次术语加短解释，以读者使用情境组织结构；保留关键硬件、采样率、输入输出和评测条件。

每篇都像同一个模板：固定栏目声音，放宽章节数量和结构；要求论述顺序由资料最重要的差异决定，不强制每篇“背景/亮点/影响/总结”四段。

文字冗长：先减少 word_count，或在 compression.md 指定必须舍弃的次要信息类型。保留核心数字及适用条件；把篇幅问题与语气问题分别测试。

句式机械：添加“长短句交替”“不重复每节结尾”“不用多次三连排比”等可观察规则，并检查是否造成碎片句过多。

标题缺乏吸引力：要求具体对象、关键变化和读者问题，不靠夸大。对相同来源单独对比标题规则，避免顺带改变正文事实。

## 参数与限制

默认 temperature=0.45，审稿 0.15；降低温度通常能减少变动，但不能代替清晰指令。提高 max_tokens 仅增加输出容量，不会自动让文案更好；字数、JSON 验证和压缩共同限制输出。

写作阶段的关键事实仍需 [S编号] 供 Agent 核对；呈现层会移除人工稿中的编号、脚注、工作注释和参考列表，将出处留在独立参考框与 agent_evidence 中。调整风格时不要删除内部证据或编造实验。审稿按 sources 核对当前正文，fact_checks 保留来源编号；不能因人工稿不显示编号而误判来源缺失。修改配置后刷新 GUI 读取默认值；不要在同轮写作与审稿中途修改配置。

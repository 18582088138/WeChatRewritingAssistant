# GUI 优化记录

使用 [taste-skill / design-taste-frontend](https://github.com/leonxlnx/taste-skill/tree/main/skills/taste-skill)，应用其 app-screens 流程；当前使用的规范已安装在本机 Codex skills 目录。

设计方向：**Editorial greeting / Open plane**，seed **54466710**。保留 Signal Studio 品牌绿色和 DM Sans，并以 Microsoft YaHei / PingFang SC 承载中文。没有重抽设计方向。绘制脚本建议的 sell-out-strip 与本文编辑业务无关，因此用文章的“来源 → 写作 → 审稿 → 人工确认”取代它。

界面首先回答：哪篇文章需要处理，下一步是什么？产品自身的来源记录、审稿状态、版本和草稿投递成为视觉重点。

改动包括：合并状态统计为一条可点击的筛选栏，正常显示 0 而不补零；中性导航与背景；统一 SVG 线性图标；正文 14–15px，辅助文字至少 11–12px；强化文字对比；去除装饰横幅、虚构封面、玻璃效果、静止卡片阴影和英文装饰标签。文章卡片显示出处域名和明确操作，生成的文字组图放在素材库，避免卡片重复展示标题。设置按说明与表单分区；新增可刷新恢复的 hash 入口；手机和平板导航折叠为整屏菜单，并处理焦点、Escape 和页面滚动。

## 验证

优化前，taste-skill 在 1440 / 768 / 390px 检出 6 类 FAIL：UI 表情、渐变、按钮阴影、对比度、字号过小和手机面板阴影；另有装饰小标签 WARN。

优化后，文章目录和设置页在以上三种宽度均为 **0 FAIL / 0 WARN**。编辑页 **0 FAIL / 1 WARN**：长正文导致草稿投递和部分审稿区在首屏以下。保留完整可编辑正文，不为压缩首屏裁掉用户内容；创作设置和保存动作仍可直接操作。这是编辑页的明确取舍。

源代码 lint **0 FAIL / 1 WARN**：仅原生 dialog 有浮层阴影，符合应用规范对真实浮层的许可；其他静止面板没有阴影。桌面与手机浏览器验证通过文章目录、筛选、设置、编辑保存、图文预览、修订记录、组图和 ZIP 下载，无脚本异常或横向溢出。

没有新增装饰照片或第三方图像。界面示例仍仅用于显式选择的预览，三篇示例文案不代表真实抓取或生成。实际文章来自后端数据。

## 最后一轮视觉复核

ROUND 2

Seen in one second: 文章目录与保存、导入动作。

Idea (one sentence): 让行业信号的来源、审稿和修订记录成为内容工作台的组织线索。

Live thing: 从状态统计和筛选进入真实文章，编辑、审稿、选择配图和准备草稿。

Layout words by section: shell=开放平面 / 状态=分栏统计 / 文章=内容卡片 / 设置=说明与表单 / 编辑=正文与创作侧栏。

Scores (主观自评，应用界面标准): design 7.8 · usability 8.2 · creativity 7.0 · content 8.2 → overall 7.8。

Caps applied: 应用界面没有营销页的照片、动画或双行文章标题要求；文案使用用户实际标题，手机允许完整换行。

Top three problems and fixes:

1. 原手机目录在顶部状态卡片和横幅后才出现文章：压缩统计栏并去掉手机横幅。
2. 原文章封面裁切文字组图，重复正文标题：文字组图留在素材库，文章列表展示正文摘要和来源。
3. 设置辅助文字占比过高：调为 13px，保留 11–12px 仅用于状态和元数据。

Remaining: 长篇编辑页仍需滚动查看审稿与投递，后续可在实际使用反馈中考虑侧栏折叠或专用标签页。

## 本轮参考资料与分页调整

本轮继续应用 design-taste-frontend，方向为 editorial-greeting，seed 92557524，保留现有 palette/type，没有重新抽取。工作台的问题是“这篇稿子的事实和素材从哪里来，下一步怎么改”；正文占主要区域，侧面资料浮窗集中证据。纸张色用于资料与预览，实际来源截图和媒体形成产品识别，不添加装饰图片。

新增多来源选区融合、材料导入、图片/视频插入、手机分页预览和素材分页。手机保留常规编辑和材料操作，隐藏 PC 专属融合，导航折叠。审稿反馈移到侧栏前部，方便先看问题再调生成参数。

检查覆盖 1440/768/390px。目录第一轮出现文字卡片的空白带，改为不拉伸卡片；第二轮出现带图与无图卡片高度不齐，内部目录可展示真实待确认来源图，纯文字卡片单独占行。最终目录 0 FAIL / 0 WARN。编辑页初次反馈 below-fold，调整审稿顺序后最终 0 FAIL / 0 WARN；没有允许跳过检查项。

已实际阅览目录三种宽度、资料浮窗和手机预览截图。状态统计由本地文章计算；测试文章和来源均为实际数据，不存在等待替换的假数据。组图采用原生分页排版，含实际参考图片，整段内容不会因画布高度而静默截断。

自评（主观）：设计 8.0、可操作性 8.4、产品特征 8.0、内容可信度 8.2。改善重点是证据与稿件并置、视频可用、手机单页阅读。长稿仍会产生较多卡片，发布前需要编辑内容；模型生成风格还应按真实复测反馈持续迭代。

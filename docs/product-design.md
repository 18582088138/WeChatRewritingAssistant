# 产品设计：本地科技内容工作台

本轮目标是一个完整的本地应用：输入公开新闻或论文链接，整理有来源的参考资料包，生成含配图的原创中文科技解读，通过独立审稿和人工编辑完成文案，再准备各平台草稿。前后端代码分离，同一 Python 服务提供 GUI、API、抓取和文件存储。本轮不部署 GitHub Pages。

## 使用者与核心任务

使用者是持续发布 AI、大模型、具身智能、芯片及 AI 软硬件解读的个人编辑。工作重点是核对事实、形成自己的论述、复用资料素材、统一栏目语言和准备图文。PC 完整编辑；手机用于查看目录、预览、常规修稿、素材添加与草稿准备。多来源文本选区融合只在 PC 显示。

## 信息结构

| 页面 | 用户需要得到的答案 | 主要操作 |
| --- | --- | --- |
| 文章目录 | 有哪些要闻，处理到哪里 | 导入链接、筛选 New/Process/Done、点击进入 |
| 单篇编辑 | 当前稿子写了什么，哪些事实需要核对 | 保存、生成、复审、按意见修改、选区重写 |
| 图文预览 | 手机逐页阅读是否清楚 | 上一页/下一页，查看实际本地配图 |
| 参考资料浮窗 | 有哪些可用事实和媒体 | 选择文章/段落、融合插入、图片/视频插入 |
| 来源与素材 | 来源及素材是否可靠、可用 | 原文链接、日期、质量诊断、授权水印确认、组图预览 |
| 修订记录 | 改了什么，之前的稿子是什么 | 阶段快照阅览 |
| 设置与连接 | 模型及平台能否使用 | 连接状态、访问令牌、公众号作者和封面配置 |

## 端到端流程

1. 导入链接，立即创建任务；后台抓取主文正文、日期、图片、直接视频和外部播放器信息。抓取后归档目录使用原文标题。
2. 提取模型/技术实体，查询新闻发布日期前后 3 天的相关报道；抓取候选正文后再次检查实体与日期。搜索引擎时间条件只是候选筛选，正文检查才决定是否纳入。
3. 直接相关的原始论文或基础科普允许越过日期窗口，标为 background。没有日期的普通新闻不自动纳入。人工补充资料标为 manual，不伪装成已核实的同期新闻。
4. 主文、关联资料、用户补充文本及其媒体共同组成资料包。写作 Agent 使用分配后的来源上下文，融合事实、组织新的结构，输出标题、摘要、关键词和带来源编号的 Markdown 图文。
5. 一轮写作与一轮审稿组成一次文章生成，分别保存快照。审稿 Agent 检查技术细节、出处、排版、自然语言、相似性与平台风险。Done 表示流程结束，仍可能需要人工处理高风险意见。
6. 编辑者核对原文，调整文案或配图，保存后旧审稿失效。按反馈修改会重新写作并复审；选区重写和资料融合仅改变选区或插入位置，随后可独立复审。
7. 生成 3:4 分页组图，检查阅读顺序、配图和来源。确认需要使用的素材后准备平台草稿或导出包，最终发布由用户在平台执行。

## 状态与版本

| 状态 | 含义 | 失败恢复 |
| --- | --- | --- |
| New | 已导入，尚无生成正文 | 抓取或生成失败可重试 |
| Process | 主文抓取、写作或审稿执行中 | 同文章互斥；重启后中断任务解除占用 |
| Done | 已有文案，当前轮完成 | 结合 stage/error/review 判断是否需要处理 |

正文保存、局部重写、资料融合都会增加 revision。编辑 API 校验 revision，防止旧窗口覆盖新稿。参考材料或素材确认发生变化会清空审稿；审稿记录带 draft_revision。文件版本保存在 versions，标题稿保存在 drafts。超限等被拒绝的模型输出也保存在 generated/attempts，避免丢失尝试稿。

## 搜索与抓取质量

默认窗口 ±3 天，可修改 config/research.json。资料纳入记录包含匹配实体、资料类型、相对发布日期天数和拒绝原因。网页/PDF 原始文件、提取正文、质量报告分项落盘，保留原文链接。下载有字节、数量、尺寸、格式和重定向限制；临时网络错误有限重试，失败不计作成功素材。

图片解码后保存并记录尺寸、哈希、来源和下载结果，GIF 保留动画。可直接下载的 MP4/MOV/WebM 保存本地；播放器链接、m3u8/MPD 分段流等记录来源和未下载原因。当前没有登录、验证码处理或通用 JavaScript 网页渲染。下载失败、来源缺少日期或无搜索结果均在界面/归档中保留诊断。

自动相关性检查以精确模型/技术实体为基础，不能保证召回全部相关资料。用户可以补充链接或文件纠正资料包。审稿核对的是可获得的来源，不等价于独立技术实验。

## 素材与人工融合

浮窗提供文章/图片/视频三种视图。文章按页阅读，PC 可跨页、跨来源加入多个选区；提交时转换 JavaScript UTF-16 位置为 Python Unicode 码点，调用真实 LLM 融合后插入原稿光标。来源编号无效或模型调用失败时原稿不变。

GUI 上传和直接复制到 manual/images、manual/videos、manual/texts 均可添加材料。打开文章或点击同步时扫描，按文件内容哈希去重；更新同路径素材后重新标为待确认。PDF/HTML 手动导入用于文本参考，媒体请独立添加。移动端保留材料查看与媒体插入，隐藏多段文字融合。

来源媒体先用于内部图文预览，授权和水印状态可见；只有确认的素材进入导出包。卡片继承所用图片的确认状态。公众号正文存在未确认图片时拒绝写入草稿。系统不会自动宣称图片无水印或拥有许可。

## 语言与图文设计

统一采用“专业、自然、克制的中文科技解读，保留关键技术细节”。风格独立于基础写作 prompt，便于逐次优化；审稿要检查数字条件、结论强度、套话和原文结构复刻。调整方法见 prompt-style-guide.md。

GUI 以正文工作区为中心，右侧参考浮窗承载证据；保留现有低饱和绿色、纸张预览和 DM Sans 字体。PC 使用正文与辅助栏，手机折叠导航、单列工作区和分页预览。

组图为 1080×1440 PNG，默认每页约 240 字符，保持字体不低于 26 px。封面呈现标题、摘要和实际素材；正文合并短段落，在标题或图片处换页，长内容拆分保留。内容超出最小字号容量时报错，不静默裁掉正文。正文 HTML 预览采用独立分页，导出 HTML 保留完整稿件。长稿可能生成较多卡片，应按选定平台需求缩短稿件或分批使用。

## 配置与安装

config 保存 app/research/generation/platforms JSON 及 rewriting/reviewing/language-style/fusion prompts。密钥仅在 .env。生成记录配置指纹并归档 config-history 便于对照，修改运行参数和 prompts 后新请求读取最新配置；服务地址修改后重启。

Windows 在本机已有 conda 的前提下双击 Install.cmd 安装依赖/创建指定环境，双击 Start.cmd 启动完整应用并打开浏览器。Linux 提供 install.sh/start.sh。当前运行一个 Uvicorn worker，数据在本地文件系统。Dockerfile/compose 为后续统一 Python 平台打包入口，本轮未验收容器或外部部署。

## 平台范围

微信公众号有配置且满足接口权限时，仅写 draft/add。X、小红书、微博当前准备平台文案和图文包，由用户手动存草稿；尚未实现统一远程草稿写入，界面区分 export_ready 与 draft_saved。全部平台最终发布由用户操作，不调用直接发布接口。

## 本轮验收标准

三条用户链接完成真实抓取、关联搜索、写作审稿、人工保存/选区操作、配图、分页组图和四平台素材包导出；GIF 与可下载视频检查格式及内容；PC/手机无页面横向溢出；资料融合使用真实模型且保留未选中正文；已有归档迁移可追溯；参数与 prompts 可编辑；一键安装/启动有效；文档与实现一致。具体结果和剩余边界见 local-product-validation.md。
